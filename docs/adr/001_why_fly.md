# ADR-001: バックエンドインフラにFly.ioを採用する

## ステータス
採用済み（フェーズ1）

## コンテキスト
GoのAPIサーバーをホスティングするインフラを選定する必要があった。
候補はFly.io・AWS ECS Fargate・Railway・Renderだった。

## 決定事項
フェーズ1（0〜10サロン・クリニック）ではFly.ioを採用する。

## 理由
- 月額$3〜5と初期フェーズのコストを最小化できる
- Dockerコンテナをそのままデプロイできる
- Terraform Providerが存在しIaC管理が可能
- フェーズ1のトラフィックに対して十分な性能がある
- GitHub Actionsとの連携が容易でCI/CDをシンプルに保てる

## トレードオフ
- AWS ECS Fargateと比較するとオートスケールの柔軟性が低い
- 大規模トラフィック時の対応力に限界がある

## 移行トリガー条件
以下のいずれかを満たした時点でAWS ECS Fargateに移行する。
- テナント数が10〜50店舗を超えた時
- オートスケールの要件が発生した時
- 可用性要件がFly.ioの提供範囲を超えた時
